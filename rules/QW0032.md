# QW0032: Round converted double values

In .NET 11.0, the conversion from `double` to `decimal` is
[correctly](https://github.com/dotnet/runtime/pull/130566) rounded. Previously,
only 15 significant decimal digits were retained, which could hide the difference
between a binary floating-point value and a decimal value. As a result,
`(decimal)1.23` now converts to `1.229999999999999982236431606` instead of `1.23`.

The reasoning about this rule is that the pre .NET 11.0 behavior might have
been *exploited* as a feature rarther then considered a bug, and as the
behavior changed, should be evaluated correctly. For [greenfield projects](https://en.wikipedia.org/wiki/Greenfield_project)
only targeting .NET 11.0 and up, this rule might be disabled.

More info about floating points can be read at [0.30000000000000004.com](https://0.30000000000000004.com)

## Non-compliant
```csharp
decimal a = (decimal)value;
decimal b = new decimal(value);
decimal c = Convert.ToDecimal(value);
decimal d = (decimal)123.4567;
decimal e = (decimal)Math.Round(value, 2);
```

## Compliant
```csharp
decimal a = Math.Round((decimal)value, 2);
decimal b = decimal.Round((decimal)value, 2);
decimal c = 123.4567m;
```
